# Independent Audit Resolution Matrix (BUG-01 through BUG-17)

**Audit Release:** Naukri Application Clarity V2.2  
**Audit Date:** 28 November 2026  
**Test Harness:** `test_runner_real.js` (Node.js executable assertions on pure domain functions)  
**Status:** All 17 identified audit defects systematically resolved and verified by executable tests.

---

| Bug ID | Audit Defect Description | Root Cause | Architectural & Code Fix in V2.2 | Executable Verification Assertion | Status |
|---|---|---|---|---|---|
| **BUG-01** | Premature Attendance Confirmation: Candidate could confirm attendance days before interview occurrence. | `recordAttendance()` allowed immediate timestamp recording regardless of `interview.starts_at`. | Implemented strict premature check in `interview-domain.js`: if simulated `DemoClock.now()` < `interview.starts_at`, operation is rejected with descriptive error. Added UI Demo Clock controls (+2h, +1d, +7d). | `assert.throws(() => Domain.recordAttendance(state, { interview_id: 'int-01', actor_role: 'candidate', result: 'positive' }), /Cannot record attendance before interview occurrence/);` | ✅ Resolved & Verified |
| **BUG-02** | CAIR 14-Day Window Drift: Observation window used 14.5 days instead of exact 14.0 days. | PRD drift in test harness allowed extra 12-hour grace period (`14.5 * 86400 * 1000`). | Replaced window boundary with exact constant `14 * 86400 * 1000 ms`. Tested exact boundary conditions at 14.0d (qualifies) and 14.0d + 1ms (disqualified). | `assert.strictEqual(cairExact.rate_pct, 100.0); assert.strictEqual(cairLate.rate_pct, 0.0);` | ✅ Resolved & Verified |
| **BUG-03** | Silent Fallback for Missing Seeker ID: Denominator assigned missing seeker IDs to `seeker-01`. | Defensive nullish coalescing `app.seekerId || 'seeker-01'` masked corrupt data. | Removed silent fallback: `calculateCAIR()` explicitly drops/rejects invalid applications missing stable `seekerId`, `jobId`, or invalid date formats. | `assert.strictEqual(cairMissing.eligible_cohort_size, 0);` | ✅ Resolved & Verified |
| **BUG-04** | Multiple Interviews per Application: Application state restricted tracking to a single active interview. | Fixed 1:1 schema mapping in candidate card. | Domain logic now indexes interviews by `interview_id`, maintaining application-level array of rounds while preventing concurrent active invitations for the same round. | `assert.strictEqual(appInterviews.length, 2);` | ✅ Resolved & Verified |
| **BUG-05** | Loss of Completed Interview Data on Withdrawal: Application withdrawal purged interview progression records. | Destructive cascade cancelled all interviews irrespective of completion status. | Withdrawal now cancels only active uncompleted interviews (`starts_at > now` or unconfirmed). Completed interviews, dual attendance confirmations, and historical timeline entries remain preserved. | `assert.strictEqual(intComp.outcome.status, 'Confirmed'); assert.strictEqual(intComp.cancellation, null);` | ✅ Resolved & Verified |
| **BUG-06** | Cancelled Interviews Included in CAIR Numerator: Cancelled-before-occurrence interviews were improperly evaluated. | Numerator query checked candidate attendance timestamp without verifying cancellation flag. | Enforced check: if `interview.cancellation && interview.cancellation.cancelled`, `deriveOutcome()` immediately returns `Cancelled` and `qualified = false`. | `assert.strictEqual(outcome.status, 'Cancelled'); assert.strictEqual(outcome.qualified, false);` | ✅ Resolved & Verified |
| **BUG-07** | Inconsistent Negative + Unknown Outcome: Candidate negative + recruiter unknown gave unclassified state. | Missing branch in state derivation table. | Implemented standardized 7-state attendance derivation: Candidate Negative + Recruiter Unknown maps strictly to `'Reported Non-Attendance, Awaiting Other Party'`. | `assert.strictEqual(outcome.status, 'Reported Non-Attendance, Awaiting Other Party');` | ✅ Resolved & Verified |
| **BUG-08** | Stale Notification Reminders on Reschedule: Reminders remained linked to old versioned slot. | Reminders lacked version association. | Invalidation engine marks existing pending reminders for that interview ID as `invalidated` whenever `confirmReschedule()` or `cancelInterview()` is called. | `assert.strictEqual(reminders[0].status, 'invalidated');` | ✅ Resolved & Verified |
| **BUG-09** | Expired Invitation Acceptance: Expired invitations could still be accepted by candidate. | Expiry date check was omitted in `respondToInvitation()`. | Added strict check: if simulated `DemoClock.now()` > `interview.invitation_expires_at`, acceptance is rejected. | `assert.throws(() => Domain.respondToInvitation(state, { interview_id: 'int-02', response: 'Accepted' }), /Invitation has expired/);` | ✅ Resolved & Verified |
| **BUG-10** | Unsanitized Attendance Roles and Values: Domain accepted arbitrary strings for role and result. | Lacked strict parameter whitelisting. | Domain now enforces `['candidate', 'recruiter'].includes(actor_role)` and `['positive', 'negative'].includes(result)`. Invalid inputs throw immediate descriptive assertions. | `assert.throws(() => Domain.recordAttendance(state, { interview_id: 'int-01', actor_role: 'admin', result: 'positive' }), /Invalid actor_role/);` | ✅ Resolved & Verified |
| **BUG-11** | Repeated Attendance Confirmation Idempotency: Multiple clicks on 'I Attended' duplicated event history. | Appended duplicate timeline and attendance objects on every invocation. | `recordAttendance()` checks existing record. Identical repeated submissions return idempotent success without mutating state or duplicate logging. | `assert.strictEqual(intBefore.attendance_candidate.recorded_at, intAfter.attendance_candidate.recorded_at);` | ✅ Resolved & Verified |
| **BUG-12** | Unaudited Attendance Corrections: Changing positive to negative overwrote previous record without trail. | In-place replacement of attendance object. | Implemented audit history array `interview.attendance_corrections`: previous confirmation is archived with timestamp and reason, ensuring forensic integrity. | `assert.strictEqual(intUpdated.attendance_corrections.length, 1);` | ✅ Resolved & Verified |
| **BUG-13** | Identical Application Records Establishing Cohort: Multiple submissions with identical application ID qualified seeker. | Ingestion lacked stable application ID deduplication. | Deduplicated submissions by application ID (`Set(seenAppIds)`). Identical repeated submissions drop to 1 unique application. | `assert.strictEqual(cair.totalEligibleSeekers, 0);` | ✅ Resolved & Verified |
| **BUG-14** | Same Job Multiple Applications Qualifying Seeker: 3 different application IDs for the exact same job ID qualified seeker. | Cohort anchor window only counted application array length without verifying unique jobs. | Sliding window now enforces a minimum of 3 distinct `jobId` records within 7 days. Anchors strictly at the 3rd distinct job. | `assert.strictEqual(cair.totalEligibleSeekers, 0);` | ✅ Resolved & Verified |
| **BUG-15** | Rescheduling Post Attendance Recording: Participant could request reschedule after attendance had already been recorded. | `proposeReschedule()` did not check for existing attendance records. | Enforced check: if candidate or recruiter attendance has been recorded, reschedule is rejected unless explicit `correction_authorized` flag is supplied. | `assert.strictEqual(resRes.success, false); assert.ok(resRes.error.includes('attendance has already been recorded'));` | ✅ Resolved & Verified |
| **BUG-16** | Recruiter Slot Substitution without Negotiation: Recruiter could confirm an arbitrary different slot from proposed slot. | `confirmReschedule()` accepted arbitrary `confirmed_slot` without matching candidate request. | Enforced slot parity: recruiter confirmation must either confirm the proposed slot directly or provide an explicit slot matching `proposed_slot.slot`. Also rejects past slots. | `assert.strictEqual(confRes.success, false); assert.ok(confRes.error.includes('Confirmed slot must match the candidate proposed slot'));` | ✅ Resolved & Verified |
| **BUG-17** | Cancellation Invalidating Completed Interviews: Recruiter cancellation could wipe completed historical interview outcomes. | `cancelInterview()` did not verify whether interview was already completed. | Protected historical records: if interview outcome is `Dual Confirmed` or `Not Attended`, cancellation is rejected and prior outcome preserved. | `assert.strictEqual(cancelRes.success, false); assert.ok(cancelRes.error.includes('Cannot cancel an already completed historical interview'));` | ✅ Resolved & Verified |
